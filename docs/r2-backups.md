## Retention policy

Keep the newest archive from each of the **seven most recent available backup dates**, measured in America/Toronto, plus the newest archive from **four additional older Monday-start weeks** not already represented by those daily copies. This retains up to eleven regular recovery points as history grows. Missing days do not cause the latest backup to expire. Multiple backups made on one date are not separate daily recovery points. Manual reference/pre-migration files remain protected outside the rotation until separately reviewed.

Run `npm run backup:retention` for a non-destructive local preview. It authenticates/decrypts archives, checks embedded data/photo checksums, uses the snapshot's internal timestamp, and requires an existing isolated-restore report before considering a regular archive for rotation. It saves names, hashes, timestamps and decisions to ignored `.folio-backups/retention-preview.json`. Unreadable/corrupt/unverified/future-dated archives, symlinks and nonstandard filenames remain protected for investigation. The prior report is not a fresh restore test; verify every proposed retained recovery point again before applying cleanup. Re-scan names/hashes before removal so a stale preview cannot govern changed files.
